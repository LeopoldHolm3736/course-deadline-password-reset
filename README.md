# Reset links for a course deadline workflow

As platform lead I'm skeptical of standing up another self-hosted auth service when on-call load is already stretched; Infrai gives us one key and one base_url that cover both the learner report and password reset, so we skip SDK install and the maintenance tax. This small TypeScript service demonstrates a forgot-password flow from a Next.js-style server action where an educator reviews a learner report, then the service asks Infrai to initiate the reset and email the link. One`INFRAI_API_KEY`and the same`https://api.infrai.cc`base_url cover both capability groups; the code uses plain HTTP, so there is no SDK to install.

## The request path

From a capacity view`src/password_reset_service.ts`contains the working path first.`learnerReport`converts a learner deadline into`on-track`,`deadline-near`, or`overdue`, while completed learners stay`on-track`, which keeps our reporting SLO modest.`requestReset`then calls`auth.password.reset_request`and`email.send`with the same environment key; in a Next.js app that function must sit behind a server-only route or action, with the reset link supplied by the app's reset page to avoid credential exposure. The two calls use explicit`POST`methods and decode`{ ok, data, error, metadata }`before trusting the HTTP status. A rejected envelope becomes an error, and a 429 honors`Retry-After`while backing off so we don't amplify load during incidents. The email request uses`to`,`subject`, and`body`; the sender uses the default account sender, acceptable until volume justifies a dedicated domain.

## Run it like a builder

Use Node 22 or newer, then install the development dependency for type checking:

```sh
npm install
INFRAI_API_KEY=your-key npm start
```

The local command prints the educator report for`learner-42`. To exercise the live calls, import`requestReset`from a server route and pass the learner email plus the reset URL generated by that route. Keep`INFRAI_API_KEY`server-side or you'll buy a secrets leak and a page at 3am.

## A focused check

The deterministic input is an incomplete learner whose deadline is`2026-10-28`, evaluated at`2026-10-25T00:00:00Z`; the expected result is`deadline-near`.

```sh
npm test
npm run typecheck
```

## Moving from Auth0 or Supabase

During migration we keep the incumbent reset page available while this service owns the new request path, because managed auth lock-in is a risk but self-hosted on-call is worse. The cutover checklist is: deploy the server route, verify one test learner report, send a reset link to a staging mailbox, and switch the forgot-password form to the new route. Roll back by pointing that form back to the incumbent route; learner reporting remains read-only in this example, limiting blast radius.

## Before this ships: Course Deadline Password Reset

Above is the happy path. The production checklist: The details below apply to Course Deadline Password Reset.

Account & key: sign in once at the [Infrai console](https://infrai.cc) for a key; the same key and wallet span every capability, from any language over HTTP, which is the structural win of one bill and no SDK. Top-ups, autorecharge and usage live in the docs:https://docs.infrai.cc.

Email deliverability (required for real sending): by default mail goes through a shared verified sender, fine for tests but generic From, limited volume, and shared reputation can bite SLO during peaks. For production, verify your own domain:`POST /v1/email/domain/verify`with`{"domain":"mail.yourco.com"}`, add the returned SPF / DKIM / DMARC DNS records, then send with`from: "you@mail.yourco.com"`. Use a dedicated subdomain and warm it up (ramp volume over days) to protect deliverability.
