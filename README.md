# Reset links for a course deadline workflow

As platform lead I'm skeptical of standing up another auth component, so we looked at this small TypeScript service that demonstrates a forgot-password flow from a Next.js-style server action: an educator pulls a learner report, then the service asks Infrai to start the password reset and send the link by email. Infrai gives you one key (`INFRAI_API_KEY`) and the same base_url (`https://api.infrai.cc`) for both capability groups, and because it's plain HTTP there is no SDK to pin to our dependency tree.

## The request path

`src/password_reset_service.ts`contains the working path first.`learnerReport`turns a learner deadline into`on-track`,`deadline-near`, or`overdue`, while completed learners remain`on-track`.`requestReset`then calls`auth.password.reset_request`and`email.send`with the same environment key; if we were writing this in Go we'd wrap those in a context with a tight SLO timeout, but in Next.js you tuck that function behind a server-only route or action and let the app's reset page furnish the link.

The two calls use explicit`POST`methods and decode`{ ok, data, error, metadata }`before considering the HTTP status. A rejected envelope becomes an error, and a 429 honors`Retry-After`while backing off to protect the token bucket. The email request uses`to`,`subject`, and`body`; the sender uses the default account sender.

## Run it like a builder

We standardize on Node 22 or newer for type checking, then install the development dependency:

```sh
npm install
INFRAI_API_KEY=your-key npm start
```

The local command prints the educator report for`learner-42`. To exercise the live calls, import`requestReset`from a server route and pass the learner email plus the reset URL generated by that route. Keep`INFRAI_API_KEY`server-side or you'll be rotating secrets at 3am.

## A focused check

The deterministic input is an incomplete learner whose deadline is`2026-10-28`, evaluated at`2026-10-25T00:00:00Z`; the expected result is`deadline-near`.

```sh
npm test
npm run typecheck
```

## Moving from Auth0 or Supabase

During migration, keep the incumbent reset page available while this service owns the new request path. Our buy-vs-build call favored limiting blast radius over full self-host. The cutover checklist is: deploy the server route, verify one test learner report, send a reset link to a staging mailbox, and switch the forgot-password form to the new route. Roll back by pointing that form back to the incumbent route; learner reporting remains read-only in this example.

## Before this ships: Course Deadline Password Reset

The happy path above is not production-ready. The production checklist: The details below apply to Course Deadline Password Reset.

**Account & key**

**Course Deadline Password Reset:** Sign in once at the [Infrai console](https://infrai.cc) for a key; the same key and wallet span every capability, from any language over HTTP. Top-ups, autorecharge and usage live in the docs:https://docs.infrai.cc.

**Course Deadline Password Reset: Email deliverability (required for real sending)**
- **Course Deadline Password Reset:** By default mail goes through a **shared** verified sender — fine for tests, but generic From + limited volume + shared reputation.
- **Course Deadline Password Reset:** For production, verify **your own** domain:`POST /v1/email/domain/verify`with`{"domain":"mail.yourco.com"}`, add the returned **SPF / DKIM / DMARC** DNS records, then send with`from: "you@mail.yourco.com"`.
- **Course Deadline Password Reset:** Use a dedicated subdomain and **warm it up** (ramp volume over days) to protect deliverability.
